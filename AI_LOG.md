# Как я работал с AI

Проект сделан в паре с AI-ассистентом **Claude Code** (модель Claude Opus). Полная переписка с ассистентом сохранена в виде выгрузки сессии и не удалена — её можно показать по запросу.

## Порядок работы

1. **Сначала план, потом код.** Я дал ассистенту текст задания и попросил не писать код, а предложить план: технологии, хранение данных, шаги. План обсудили, затем расширили, когда стало понятно, что жёсткого ограничения по времени нет.
2. **Маленькие шаги.** Работа разбита на 7 шагов. После каждого шага я проверял результат руками по чек-листу, который давал ассистент, и только потом просил сделать коммит. Поэтому каждый коммит в истории — один законченный и проверенный шаг.
3. **Каждый шаг проверяется трижды:** автотестами (`npm test`), запуском живого сервера и прохождением сценария в настоящем браузере (в том числе на ширине телефона), и затем моей ручной проверкой.

## Шаги

| Шаг | Что сделано |
|---|---|
| 0 | Каркас: Express, порт из `PORT`, понятные ошибки при занятом и неверном порте |
| 1 | Хранилище `data/db.json` (атомарная запись, очередь изменений) и API форм |
| 2 | Админка: список форм и конструктор |
| 3 | Публичная форма для студента, проверка ответов, снимок вопросов в ответе, предпросмотр |
| 4 | Просмотр ответов, поиск, выгрузка CSV для Excel |
| 5 | Аналитика брошенных форм: воронка, вопросы, на которых уходят, подсказки |
| 6 | Черновик ответов в браузере, прогресс заполнения, демо-форма, проверка на Node 20 |

## Какие решения принимались и почему

Ключевые решения объяснены в README и в комментариях в коде. Коротко:

- **JSON-файлы вместо SQLite** — чтобы `npm install` гарантированно работал без компилятора и на Node 20.
- **Без React и сборки** — экранов немного, а `npm start` должен просто запускать сервер.
- **Общий код для браузера и сервера** (`src/shared/`) — правила проверки ответов описаны один раз.
- **Отдельный журнал событий** для аналитики, который только дописывается.
- **Защита пользовательских данных**: вывод только как текст, Content-Security-Policy, защита от CSV-инъекции, аналитика без ответов, cookie и IP.

## Что нашла проверка в браузере

Не всё получилось с первого раза. Ошибки, которые нашлись при проверке и были исправлены до коммита:

- Браузер кешировал ответ «приём закрыт», и после повторного открытия приёма студент продолжал видеть старый статус. Исправлено заголовком `Cache-Control: no-store` для API и закреплено тестом.
- Заголовок вопроса с вариантами налезал на рамку карточки (особенность `<fieldset>`).
- Колонки таблицы ответов сжимались так, что почта рвалась посередине.
- При уходе со страницы браузер присылает два сигнала, и «уход» записывался в аналитику дважды.
- Отдельный лимит размера для маршрута событий не работал, потому что тело уже разобрано общим обработчиком — лишний код убран, вместо этого ограничено число событий в пачке.

Ассистент писал код и тесты, а я ставил задачу, принимал решения на развилках, проверял каждый шаг руками и решал, когда делать коммит.
