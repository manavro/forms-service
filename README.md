# Сервис форм отклика

Менеджер собирает форму отклика в админке и получает ссылку. Студент по ссылке заполняет форму. Менеджер смотрит ответы и видит, на каком шаге студенты бросают заполнение.

Тестовое задание на стажировку «Младший веб-разработчик (AI-assisted)». Как шла работа с AI — в [AI_LOG.md](AI_LOG.md).

## Запуск

Нужен Node.js 20 или новее (проверено на 20.20 и 24.19). Ничего, кроме Node.js, устанавливать не нужно: никаких баз данных, API-ключей и внешних сервисов.

```bash
npm install
npm start
```

После запуска:

- админка: http://localhost:3000/admin
- проверка, что сервер жив: http://localhost:3000/api/health

### Что посмотреть за пару минут

При самом первом запуске сервис создаёт опубликованную **демо-форму** со всеми типами полей (ссылка на неё печатается в консоли), поэтому админка не пустая.

1. Откройте http://localhost:3000/admin → демо-форму → «Конструктор»: поменяйте вопрос, нажмите «Предпросмотр».
2. Скопируйте ссылку для студентов и откройте её в окне инкогнито. Заполните часть формы, закройте вкладку, откройте ссылку снова — ответы восстановятся. Отправьте ответ.
3. Вернитесь в админку → «Ответы»: ответ в таблице, его можно открыть целиком или скачать все ответы в CSV.
4. «Аналитика»: воронка и статистика по вопросам. Брошенной сессия считается через 30 минут бездействия, до этого она в «заполняют сейчас».

## Админка

Адрес: http://localhost:3000/admin (без авторизации, как требует задание; в реальном продукте её нужно закрыть входом).

- **Список форм**: статус, число полей и ответов, дата изменения. Отсюда форму можно открыть, скопировать ссылку для студентов, создать копию или удалить.
- **Конструктор**: название, описание и поля. Поле можно добавить, переставить стрелками, продублировать, удалить, сменить тип, сделать обязательным, задать подсказку и пример ответа. Для полей с выбором — список вариантов (Enter в варианте добавляет следующий).
- **Сохранение** — кнопкой или Ctrl+S. Ошибки показываются рядом с конкретным полем. При попытке уйти со страницы с несохранёнными изменениями браузер предупредит.
- **Публикация** даёт ссылку вида `/f/<код>`, её можно скопировать в один клик. Приём ответов можно закрыть и открыть снова.
- Если форму одновременно правят в двух вкладках, вторая не затрёт изменения первой: сохранение остановится с понятным сообщением.
- **Предпросмотр** показывает форму глазами студента, включая несохранённые правки. Ответ из предпросмотра никуда не отправляется.

## Просмотр ответов

Вкладка «Ответы» у формы (`/admin/forms/<id>/responses`), туда же ведёт кнопка «Ответы (N)» в списке форм.

- **Таблица**: колонки — вопросы, строки — ответы, свежие сверху (порядок можно поменять). Длинные ответы в таблице обрезаются до трёх строк.
- **Поиск** по всем ответам сразу — например, по фамилии или почте.
- **Ответ целиком** открывается по клику на строку. Ответы можно листать стрелками, а тестовый ответ — удалить.
- **Изменённые вопросы.** Колонки соответствуют текущим вопросам формы; ответы на удалённые вопросы остаются отдельными колонками с пометкой «вопрос удалён». Если вопрос переименовали, в окне ответа видно, как он звучал в момент ответа.
- **Скачать CSV для Excel.** Файл открывается в Excel двойным щелчком без настройки импорта: разделитель «;» (его ждёт Excel с русскими настройками) и BOM, чтобы кириллица не превратилась в «кракозябры». Значения, начинающиеся с `=`, `+`, `-`, `@`, начинаются с апострофа: так Excel не выполнит их как формулу (защита от CSV-инъекции — ответ пишет посторонний человек).

## Аналитика: где студенты бросают форму

Вкладка «Аналитика» у формы (`/admin/forms/<id>/analytics`). Отвечает на вторую проблему из задания — почему студенты не доходят до отправки.

- **Главные цифры**: сколько открыли форму, начали, отправили, бросили и заполняют прямо сейчас.
- **Воронка** «открыли → начали → отправили» с потерями на каждом шаге.
- **По вопросам**: сколько студентов дошли до вопроса, сколько бросили форму именно на нём, сколько видели в нём ошибку и сколько времени обычно на него уходит (медиана). Вопрос, на котором уходят чаще всего, отмечен.
- **Подсказки «Что можно улучшить»** — правила по данным: «на этом вопросе бросают чаще всего — нужен ли он?», «здесь часто ошибаются — уточните пример», «многие уходят, не начав — проверьте описание». Выводы появляются только при минимальном объёме данных, иначе честно сказано, что данных мало.
- Период: всё время, 30 или 7 дней. Кнопка «Сбросить аналитику» — после собственных тестовых заполнений.

**Как собираются данные.** Страница формы отправляет короткие события: открыл форму, перешёл к вопросу, впервые что-то ввёл, увидел ошибку, ушёл со страницы. Событие «отправил» пишет сам сервер, когда сохраняет ответ. Сами ответы, cookie и IP-адреса в аналитику не попадают; номер сессии случайный и живёт только в открытой вкладке. При уходе со страницы оставшиеся события отправляются через `navigator.sendBeacon`, чтобы не потеряться.

**Как считается.** Сессия — одно открытие формы. «Бросили» — начали, не отправили и ничего не делали больше 30 минут; кто активен недавно, считается «заполняют сейчас». «Бросили на вопросе» — вопрос, с которым студент работал последним. Время — медиана, чтобы одна забытая открытой вкладка не искажала цифру. Расчёт — в `src/analytics/computeAnalytics.js`.

**Где хранится.** В отдельном файле `data/events.jsonl` (одна строка — одно событие), а не в `db.json`: событий намного больше, чем ответов, и их выгодно дописывать в конец файла, а не переписывать весь файл. Если сервер упадёт во время записи, пострадает максимум последняя строка — при чтении она пропускается. Публичный приём событий проверяет форму, типы событий и поля и ограничивает число событий в одной сессии. Удаление ответа удаляет и его сессию из аналитики, удаление формы — все её события.

## Форма для студента

Адрес — ссылка из админки: `http://localhost:3000/f/<код>`.

- Вёрстка рассчитана в первую очередь на телефон: крупные поля и варианты, по которым легко попасть пальцем.
- **Черновик.** Ответы сохраняются в браузере студента (localStorage) по мере ввода. Если закрыть вкладку и вернуться по той же ссылке, ответы восстановятся, а кнопка «Начать заново» их сотрёт. Черновик никуда не отправляется, удаляется после отправки ответа и сам — через неделю. Это прямо уменьшает число брошенных форм.
- **Прогресс** над формой: «Заполнено 4 из 8 · обязательных осталось: 2». Полоска прилипает к верху экрана при прокрутке.
- Ответы проверяются в браузере (сразу) и на сервере (окончательно) по одним и тем же правилам из `src/shared/answers.js`.
- Ошибка показывается, когда студент уходит из заполненного поля. Пустые обязательные поля подсвечиваются только при попытке отправить. Над формой появляется список ошибок со ссылками на нужные вопросы.
- Если форма ещё черновик или ссылка неверная — «Форма не найдена». Если приём закрыт — «Приём ответов завершён». После отправки — «Спасибо! Ответ отправлен».
- Повторная отправка того же ответа (двойной клик, повтор после сбоя сети) не создаёт дубль: у каждой попытки заполнения есть свой номер.
- Скрытое поле-ловушка отсекает простых ботов: человек его не видит, а бот заполняет — такой ответ не сохраняется.

**Ответ хранится вместе с текстами вопросов.** Если менеджер потом переименует или удалит вопрос, старые ответы останутся понятными. Для вариантов сохраняются и id, и подпись.

Интерфейс написан на обычном JavaScript без фреймворков и сборки: страниц немного, а `npm start` должен просто запускать сервер. Пользовательский текст всегда выводится как текст (не как HTML), а заголовок `Content-Security-Policy` запрещает браузеру выполнять чужие скрипты — это защита от XSS.

## Что сознательно не сделано

- **Авторизация в админке** — по заданию админка доступна без входа. В реальном продукте это первое, что нужно добавить.
- **Загрузка файлов (резюме)** — потребовала бы хранения файлов, проверки их типа и размера; для MVP достаточно текстовых полей.
- **Условная логика** («показать вопрос, если выбрано…») — заметно усложняет конструктор и проверку ответов.
- **Масштаб.** Данные целиком держатся в памяти и пишутся в JSON-файлы. Для сотен форм и десятков тысяч ответов этого хватит; дальше хранилище нужно перенести в базу данных — весь доступ к файлам собран в `src/storage/`.
- **Защита публичных адресов от перегрузки** (ограничение запросов с одного адреса). Сейчас есть ловушка для ботов, лимиты размера и числа событий; ограничение по IP не добавлено, потому что студенты одного вуза часто выходят в интернет с одного адреса.

## Хранение данных

Формы и ответы лежат в `data/db.json` — обычном JSON-файле, его можно открыть и посмотреть. События аналитики — в `data/events.jsonl` (см. раздел «Аналитика»). Папка создаётся при первом запуске и не попадает в git.

Почему JSON, а не SQLite: популярный пакет `better-sqlite3` содержит нативный код и на некоторых системах требует компилятора при `npm install`, а встроенный `node:sqlite` есть только в Node.js 22+. JSON-файл работает везде без дополнительной установки. Для объёмов MVP этого достаточно; весь доступ к файлу сосредоточен в `src/storage/`, поэтому хранилище можно заменить, не трогая остальной код.

Как защищены данные:

- **Атомарная запись.** Новое содержимое пишется во временный файл, затем переименовывается поверх основного. Если процесс упадёт посреди записи, основной файл останется целым.
- **Очередь изменений.** Изменения выполняются строго по одному, одновременные запросы не перетирают друг друга.
- **Всё или ничего.** Изменение применяется к копии данных и становится текущим, только когда копия записана на диск.
- **Повреждённый файл не перезаписывается.** Сервер не запустится и сообщит, какой файл повреждён, вместо того чтобы молча начать с пустыми данными.

## API админки

| Метод и адрес | Что делает |
|---|---|
| `GET /api/forms` | список форм (без полей, с числом ответов) |
| `POST /api/forms` | создать форму-черновик |
| `GET /api/forms/:id` | форма целиком и число ответов на неё |
| `PUT /api/forms/:id` | сохранить название, описание и поля; в теле нужна `version` |
| `DELETE /api/forms/:id` | удалить форму вместе с ответами и аналитикой |
| `POST /api/forms/:id/publish` | опубликовать или снова открыть приём ответов |
| `POST /api/forms/:id/close` | закрыть приём ответов |
| `POST /api/forms/:id/duplicate` | создать копию формы |

Ответы на форму:

| Метод и адрес | Что делает |
|---|---|
| `GET /api/forms/:id/responses` | таблица ответов: колонки (вопросы) и строки (ответы), свежие сверху |
| `GET /api/forms/:id/responses/export` | то же файлом CSV для Excel |
| `DELETE /api/forms/:id/responses/:responseId` | удалить один ответ (и его сессию в аналитике) |

Аналитика:

| Метод и адрес | Что делает |
|---|---|
| `GET /api/forms/:id/analytics?days=7` | воронка, статистика по вопросам и подсказки; `days` — 7 или 30, без него — за всё время |
| `DELETE /api/forms/:id/analytics` | сбросить аналитику формы (ответы остаются) |

Публичное API (им пользуется страница студента):

| Метод и адрес | Что делает |
|---|---|
| `GET /api/public/forms/:slug` | форма для заполнения; 404 — нет такой или это черновик, 410 — приём закрыт |
| `POST /api/public/forms/:slug/responses` | отправить ответ `{ answers: { [id поля]: значение }, submissionId }`; 201 — принят |
| `POST /api/public/forms/:slug/events` | события заполнения `{ sessionId, events: [{ type, fieldId, t }] }`, до 50 за раз; 204 |

Ответы API не кешируются браузером (`Cache-Control: no-store`), чтобы, например, повторно открытый приём сразу был виден студенту.

Ошибки проверки приходят со статусом 400 и списком конкретных проблем:

```json
{
  "error": "Проверьте введённые данные",
  "details": [{ "path": "fields[0].label", "message": "Введите текст вопроса" }]
}
```

**Версия формы.** Каждое сохранение увеличивает `version`. Если форму успели сохранить в другой вкладке, запрос со старой версией получит 409, и чужие изменения не потеряются.

**Статусы формы:** `draft` (черновик) → `published` (принимает ответы) ⇄ `closed` (приём закрыт). Опубликовать форму без полей нельзя.

**Типы полей:** короткий текст, длинный текст, email, телефон, один вариант, несколько вариантов, выпадающий список, галочка (например, согласие на обработку данных). Список описан в `src/shared/fieldTypes.js` — этот файл общий для сервера и браузера.
